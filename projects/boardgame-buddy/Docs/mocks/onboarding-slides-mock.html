Onboarding as one deck

Today first-run setup is three separate polaroid modals opened back to back, and each one waits on the network before the next appears — the profile POST is awaited, the buddy batch is awaited, the BGG import holds the last card open on a 2s poll. This mock rebuilds it as a single slide deck: a step counter pinned at the top, slides that move on the same frame as the tap, and every write queued and forgotten. Tap through the phone — the ledger beside it shows what got sent while you were already two slides ahead.

tip nothing here calls a real API — writes are simulated with real-ish latencies

The four rules
1
Every step is a slide
One mounted deck, one translateX. No modal opens, closes and hands off to the next — so no gap where the user sees the empty feed behind three cards.
2
The counter is pinned
“Step 2 of 3” plus a three-segment bar, always on screen. The user knows how far in they are before they decide whether to skip.
3
Continue and Skip cycle instantly
The tap handler moves the track and returns. No await, no spinner, no disabled button, no “Sending…”. The 240ms is the slide travelling, not a request.
4
Writes are fire-and-forget
Each step queues its POST and forgets it. A failure never blocks the flow — it lands as a line on the last slide with a retry, and the permanent home for every one of these is Settings.
5
Ticking someone teaches the grid
Tick Priya on step 2 and the people she knows appear underneath, named Buddy of Priya. They arrived with the suggestions (migration 072 ships the second hop), so it costs no request and happens in the tap's own frame. It only ever appends — nothing on screen is re-rendered or moved, and an untick takes nothing back, because a grid that removes a row moves everything below it under a thumb that is still there.

What moves where

The screens keep their content. What changes is the container, the wayfinding, and when the network is allowed to matter.

Container Three polaroid-popup overlays opened in sequence, each awaiting the one before. One deck mounted once; slides on a track. Overlay chrome retired for first run.
Wayfinding None. The user learns there was a step 3 when it appears. Counter + segment bar pinned above every slide; Back returns to a filled-in slide.
Profile save await POST /profile before the buddies card opens; an error dead-ends the flow. Queued on Continue. Slide 2 is already on screen; an error surfaces on the last slide.
Buddy requests Button becomes “Sending…”, awaits /buddies/requests/bulk, then closes. Button sends and moves in the same frame. The result is a ledger line, not a wait.
Buddy suggestions Fetched between step 1 and step 2 — an empty response silently drops the step. Static once shown, and a request you send teaches the ranking nothing until it is accepted. Prefetched the moment needs_setup is seen, so slide 2 paints from a request made while the user was still naming themselves — and ships each candidate's own buddies, so ticking promotes them with no round trip. A pending request you sent is now a first-hop link server-side too.
BGG import Last card holds open on a 2s poll with a live import log. Link is queued; the import reports as one line on the finale and continues after “Start playing”.
Dismissal Closing any card leaves needs_setup true — the whole sequence returns next load. Reaching the finale clears it. Skipped steps stay offered in Settings, not re-prompted.
